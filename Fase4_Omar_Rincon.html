Abstract

This expanded technical report documents the construction and evaluation of an academic retrieval-augmented generation (RAG) assistant, including its RAG 7.2.2 browser-based PDF laboratory. The original local Python prototype used PDF extraction, multilingual embeddings, FAISS and TF-IDF retrieval, Qwen via Ollama, and Gradio. The deployed version uses Cloudflare Workers, JavaScript, BM25 for the two-document academic library (82 prepared chunks), and Workers AI. A separate temporary-PDF module supports user-selected PDF files, page-aware retrieval, document authorship questions, contextual follow-ups, formatted comparison tables, and export actions. Eleven historical academic-library answers were scored provisionally (71/88 points; seven satisfactory), while a separate six-question test sequence against Fase4_G18.pdf revealed strengths in author identification and limitations in detecting discrepancies. The report also includes evidence of completion of the IBM Skills Network-powered Cognitive Class learning path, Getting Started with Large Language Models. Results for the revised 7.2.2 comparison logic still require live verification.

Keywords: retrieval-augmented generation; academic assistant; BM25; FAISS; conversational memory; Cloudflare Workers; evaluation.

Exercise 1 — User-Centered Problem Framing and System Design

1.1. Problem, scope, and users

Academic PDF reports contain objectives, methodology, results, and conclusions spread across pages. A student or instructor needs rapid, attributable answers without manually browsing both documents. The assistant aims to retrieve and compare content of Phase 2 (restaurant data in Colombia; Python) and Phase 3 (student-performance data; R), using citations as leads for verification, not as proof of factual correctness.

1.2. User stories

  1. As a student, I want to ask about the Phase 3 objective and see the reported source pages.
  2. As an instructor, I want to compare methodologies across both reports without mixing their tools.
  3. As a reader, I want to ask “And their tools?” after a comparison without restating document names.

2.3. Conversational memory

Document selection is adapted from recent conversation history: after a two-document comparison, a short prompt such as “And their tools?” should retain both sources. After a single-document query with an explicit exclusion, a follow-up should remain in that report. In the observed eleven-answer sequence, comparative follow-up retrieval preserved both PDFs. The history buffer is short-term and does not constitute durable long-term user memory.

3.2. Error analysis

  1. Formatting compliance: tests T03 and T11 requested tables, but prose sections were returned. Improve structured output enforcement.
  2. Compound-question coverage: T07 asked for methodologies and conclusions; the response focused mostly on conclusions. Plan retrieval separately for each requested subtask.
  3. Irrelevant supplementary figures: T09 correctly noted that restaurant revenues were unavailable but supplied price examples that could distract from the question. Prefer concise refusals to infer undocumented numerical data.
  4. Citation reliability: all reported page indicators require manual validation against the primary PDFs before they can be described as verified evidence.

4. Results, Discussion, and Limitations

The preliminary average of 6.45/8 (71/88 points; 80.68% of available rubric points) suggests that most tested answers were useful while several failed presentation or coverage requirements. The proportion meeting the “satisfactory” band was 63.64% (7/11). The outcomes should not be interpreted as independently verified factual accuracy because referenced PDF passages have not been manually matched to all assertions. Observed strengths were correct tool attribution, reliable numerical counts for Phase 3 (institution: 128; subject: 122; final grade: 2), cross-document comparisons, and conversational continuity. The deployment is small-scale, with no documented load testing, long-term memory, or user-specific persistence.

5. Conclusions and Future Work (Updated)

The project demonstrates an end-to-end NLP development cycle: requirements gathering, PDF preprocessing, retrieval design, local inference, cloud adaptation, browser deployment, and empirical testing. RAG 7.2.2 adds temporary user-PDF ingestion, PDF page selection, comparison-oriented prompting and response-rendering tools. These are implemented features in the current codebase, not merely future proposals. Outstanding work includes full browser-and-cloud regression testing of RAG 7.2.2, rigorous verification of page citations, improvement of semantic retrieval for difficult cross-page comparisons, accessibility and privacy assessment, and independent volunteer evaluation. The 11 original results and the six follow-up PDF-laboratory observations are distinct assessment sets and must not be combined into a single percentage.

6. Exercise 4 — User-Uploaded PDF Laboratory (RAG 7.2.2)

From a fixed document library to temporary user-managed PDFs

The original academic assistant continues to use the prepared, two-document fragmentos.json corpus. A second, separately presented PDF laboratory allows visitors to analyze their own text-based files in the same deployed site, without changing the original 82-fragment corpus. Uploaded files are processed in browser memory; selected excerpts are transmitted to the Worker for inference. The original binary PDF is not added to the shared academic library.

6.1. Implemented capabilities

Temporary PDF loading

Up to three PDFs per browser session, at most 8 MB and 100 pages each. The client uses PDF.js to extract selectable text and split it into page-labeled fragments. Scanned/image-only PDFs are unsupported without OCR.

Dedicated RAG endpoint

The laboratory sends a question, a small set of retrieved passages, and recent turns as JSON to POST /api/upload-chat. The original academic chat remains on POST /api/chat.

Page-aware comparisons

Explicitly requested page numbers are prioritized. When required pages are missing from the retrieved excerpts, the Worker reports the limitation instead of claiming to have verified them.

Authorship and memory

Questions about authors favor author-like signals, distinguish “Presented by” from “Presented to,” and use preceding user messages to interpret follow-ups about additional contributors.

Answer presentation

Markdown tables are rendered as accessible, horizontally scrollable tables. Users can enlarge and export comparison tables to CSV and copy answers.

Session and privacy controls

Uploaded PDFs and the laboratory chat state are temporary; refreshing the page clears them. Selected document excerpts still reach Cloudflare Workers AI, so users must not submit confidential content without authorization.

6.6. Remaining limitations

Strict accuracy is not guaranteed by prompt rules alone. Responses can still misattribute facts, miss contradictory passages, or cite retrieved chunks that do not support all claims. User-supplied PDFs must contain selectable text. Client-only file memory limits persistence, and remote processing of selected passages introduces privacy considerations. Exact user-visible success rates for RAG 7.2.2 must be established through fresh tests after deployment.
